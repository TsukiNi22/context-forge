Documentation

Forge the output of any command into what you actually want to read.

context-forge is a C++20 command wrapper for Linux. It runs a program, captures one of its file descriptors, pushes the text through a pipeline of rule plugins (declared in small .cfg files) and, optionally, through a local Ollama model — then prints the result in place of the original output.

Quick start

  1. Install the binary — from the signed package repository or from source. Installation → 
    sudo curl -fsSL -o /etc/yum.repos.d/context-forge.repo https://tsukini22.github.io/context-forge/context-forge.repo
sudo rpm --import https://tsukini22.github.io/context-forge/RPM-GPG-KEY-tsukini
sudo dnf install context-forge
  2. Write a rule file — say ~/forge/rules/ls.cfg: 
    trigger = { bin = ["ls"]; };   // only for `ls`
drop = ["^total \\d+"];         // remove the "total N" line
  3. Register the daemon with your plugin and rule directories (plugins ship in the repo's plugins/ folder after a build): 
    context-forge setup --copy --recursive --plugins ./plugins --rules ~/forge/rules
context-forge status
  4. Wrap a command: 
    context-forge exec -c ls -la

Two halves. The rule engine works entirely offline. The LLM pass only activates when the server was started with a --system-prompt file and can reach an Ollama instance; otherwise it is silently skipped.

Vocabulary used across these docs

TermMeaning
clientThe context-forge exec process: spawns your command, captures one fd, talks to the server.
serverThe long-lived context-forge server process (installed as context-forge.service, a systemd user unit) that owns plugins, rules and the Ollama client.
pluginA shared object (*.so) exporting type(), name() and factory(). One of three kinds: trigger pre-rule rule.
rule fileA libconfig .cfg file. Each top-level key names a plugin (or one of the two built-ins, enable and block) and carries its settings.
binThe name of the wrapped program (argv[0] as given to -c), passed to every plugin so rules can react per program.
